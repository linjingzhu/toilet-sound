# VEIL 데모 음원과 웹 믹서

이 카탈로그는 **기능 검증용으로 직접 합성한 데모 음원**이다. 자연에서 녹음한 소리나 실제 피아니스트의 연주로 표시하지 않는다. Python 소스가 노이즈, 파형, 음표와 잔향을 계산하며 외부 녹음·샘플·음악 파일을 읽지 않는다. 실제 사용에 맞춘 음색·마스킹 효과·장시간 청취 품질은 별도 검토 대상이다.

## 제작 기록과 권리

- 제작 주체: VEIL 프로젝트. OpenAI 코딩 도우미가 작성한 절차적 합성 소스로 생성한다.
- 제작 소스: `scripts/generate_demo_audio.py`.
- 외부 녹음, 상업 음원, 샘플 라이브러리, MIDI 파일, 타인의 악보를 가져오지 않았다. 피아노풍 세 곡의 음표 배열도 이 소스에서 새로 구성했다.
- 음원마다 동일한 ID에서 얻는 고정 난수 시드를 사용한다. 생성 시 사용한 NumPy 버전과 각 WAV의 SHA-256을 `manifest.json`에 기록한다.
- 별도의 제삼자 음원 라이선스나 출처 표기 의무를 이 데모에 붙이지 않는다. 이 제작 기록은 독점적 저작권 성립 여부에 관한 법률 판단이 아니다. 출시 음원을 교체하면 새 음원의 제작자와 배포·상업 이용 권한을 따로 기록한다.

## 재생성

저장소 루트에서 다음 명령을 실행한다. NumPy 외에 추가 Python 패키지는 필요하지 않다.

```bash
python scripts/generate_demo_audio.py --output-dir app/public/app/audio
python scripts/generate_demo_audio.py --output-dir app/public/app/audio --verify-only
```

첫 명령은 WAV 13개와 `manifest.json`을 쓰고 결과를 검증한다. 둘째 명령은 기존 파일의 형식·음량·루프 경계·해시만 확인한다. 생성 파일의 소유자는 통합 담당자이며, 병렬 작업자가 같은 경로에서 중복 생성하지 않는다. 수치 연산 라이브러리나 버전 차이는 마지막 PCM 비트에 영향을 줄 수 있으므로 정확한 바이트 재현 시 매니페스트의 NumPy 버전을 사용한다.

## 카탈로그

모든 파일은 16초, 모노, 22,050 Hz, 16-bit little-endian PCM WAV이다. 웹의 기본 경로는 `/app/audio/`이며 네이티브 번들에서도 동일한 파일을 사용한다.

| ID / 파일명 | 구분 | 합성 방식 |
| --- | --- | --- |
| `water.wav` | 흐르는 물 | 넓은 대역의 연속 노이즈, 느린 질감 변화, 부드러운 기포 |
| `stream.wav` | 시냇물 | 더 가벼운 물 흐름과 분리된 고음 기포 |
| `rain.wav` | 비 | 밝은 고역 노이즈와 짧게 흩어지는 빗방울 |
| `ocean.wav` | 파도 | 16초마다 두 번 이어지는 저음 파도와 거품 층 |
| `birds.wav` | 새소리 | 간격을 둔 주파수 변조 지저귐과 낮은 배경 질감 |
| `wind.wav` | 바람 | 느리게 변하는 저음 노이즈와 희미한 바람 음색 |
| `fan.wav` | 환풍기 | 일정한 환기 노이즈와 낮은 모터 배음 |
| `white-noise.wav` | 화이트 노이즈 | 대역을 제한한 고른 주파수 에너지 |
| `pink-noise.wav` | 핑크 노이즈 | 대역 안에서 대략 1/f 전력 분포 |
| `brown-noise.wav` | 브라운 노이즈 | 대역 안에서 대략 1/f² 전력 분포 |
| `piano-calm.wav` | 차분한 피아노 | 밝은 화음의 자체 구성 아르페지오 |
| `piano-warm.wav` | 따뜻한 오후 | 촘촘한 리듬의 자체 구성 아르페지오 |
| `piano-night.wav` | 밤의 여백 | 낮은 음역의 자체 구성 아르페지오 |

음표는 감쇠하는 배음과 짧은 타격 질감으로 합성한다. 소스의 자연음 이름은 선택을 돕는 청각적 비유이며 현장 녹음이라는 뜻이 아니다.

## 음량과 루프 경계

각 파일의 디지털 피크를 0.075 이하로 맞춘다. 환경음 10개와 피아노 1개를 모두 100%로 선택하더라도 정렬된 피크를 단순 합산한 상한은 0.825다. 카탈로그의 13개 전체를 합한 보수적 상한도 0.975다. 이는 파일 합성 시의 디지털 헤드룸이며 기기 출력의 청취 안전이나 마스킹 성능을 보장하는 수치가 아니다. 동시 전환 중 잠깐 남는 페이드 노드의 실제 합산 출력은 브라우저에서 별도로 확인한다.

노이즈 필터는 한 주기를 기준으로 계산하고, 물방울·음표·잔향의 끝부분은 다음 주기의 시작으로 감는다. 양 끝 샘플을 짧고 부드럽게 맞춰 PCM 경계 점프를 1 단위 이하로 제한한다. 루프 끝마다 소리가 무음으로 빠지는 방식은 사용하지 않는다. 프로그램 검증은 경계 수치와 파일 형식에 대한 검사이며 장시간 청취 검수를 대신하지 않는다.

## 웹 믹서 동작

`createWebMixer()`는 `MixerEngine` 계약을 구현한다. 오디오 그래프는 `AudioBufferSourceNode → 트랙 GainNode → VEIL GainNode → AudioContext.destination`이다. 시스템 미디어 음량이나 다른 앱의 음량을 변경하는 API는 호출하지 않는다. [W3C Web Audio API](https://www.w3.org/TR/2021/REC-webaudio-20210617/)의 버퍼 루프·오디오 그래프·게인 자동화를 사용한다.

- `setMix()`는 바뀐 ID/파일에 대해서만 소스를 교체한다. 음량 조절이나 피아노 교체가 유지 중인 환경음 소스를 다시 만들거나 처음부터 재생하지 않는다.
- 기본 40ms 선형 게인 변화로 시작·정지·음량 변경을 부드럽게 연결한다. 빠른 슬라이더 변경은 저장한 게인 경사에서 현재 값을 계산해 이어간다.
- fetch/decode 결과가 늦게 도착해도 현재 선택·재생 의도를 다시 확인한다. 중단하거나 교체한 로드는 취소하고, 취소할 수 없는 디코드 결과도 뒤늦게 재생하지 않는다.
- 정상 디코딩된 버퍼는 해당 믹서 수명 동안 재사용한다. 정지는 소스와 그 게인을 정리하며 컨텍스트는 다음 재생을 위해 유지한다. `dispose()`는 남은 작업과 노드·타이머·이벤트 리스너·버퍼를 정리하고 컨텍스트를 닫는다.
- 음원을 하나 읽지 못해도 재생 중인 다른 소리는 유지한다. `AudioStatus.error`로 실패를 알리고 다음 `setMix()`에서 해당 파일을 다시 시도한다.
- 설정에는 선택과 음량만 저장한다. `restoreMix()`는 손상된 데이터, 잘못된 음량, 알 수 없는 ID, 중복 ID와 여러 피아노를 정리하고 언제나 `playing: false`를 반환한다.
- 출력 이름은 `브라우저 기본 출력`이다. 웹 믹서가 실제 스피커·이어폰·Bluetooth 경로를 식별했다고 표시하지 않는다.

웹 단위 테스트나 브라우저 미리보기는 Android/iPhone의 백그라운드 재생·오디오 포커스·광고 SDK와의 공존 검증이 아니다. 해당 결과는 [실기기 오디오 검증 시나리오](audio-coexistence.md)에 별도로 기록한다.
