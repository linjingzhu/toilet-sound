# VEIL 제품 요구사항

작성일: 2026-10-12 · 상태: 개발 착수용 초안 · 제품명: VEIL(가칭)

## 목적과 현재 상태

물소리, 자연음, 백색소음과 음악을 섞어 화장실에서 느끼는 소리에 대한 민망함을 줄이는 모바일 매너 앱을 만든다. Google Play와 Apple App Store 모두에서 서비스한다.

현재는 요구사항을 정리하는 단계다. 앱 구현과 실기기 검증은 아직 없다. 최신 디자인 자료는 [추가 믹서 시안](design/2026-10-12-additional-concepts.md), 기준 디자인의 결정 상태는 [사용자 결정 항목](OWNER_ACTIONS.md)의 `DESIGN-001`에서 확인한다. 이 문서는 구현 완료나 스토어 출시를 의미하지 않는다.

## 사용자가 확정한 핵심 요구

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| R-01 | 다른 앱과 동시 재생 | 유튜브 등 다른 앱과 소리를 함께 재생한다. VEIL이 상대 앱을 정지시키거나 상대 앱의 음량을 자동으로 낮추지 않는다. **최우선 개발·출시 검증 항목**이다. |
| R-02 | 소리 선택과 혼합 | 물소리, 새소리, 백색소음 등을 선택하고 여러 소리를 동시에 섞을 수 있다. |
| R-03 | 음악 혼합 | 피아노 연주 같은 음악을 환경음과 함께 들을 수 있다. 음악의 변경·정지는 이미 재생 중인 환경음을 끊지 않는다. |
| R-04 | 개별 음량과 앱 음량 | 소리별 음량과 VEIL 전체 믹스의 음량을 조절한다. 앱 전체 슬라이더의 명칭은 `VEIL 음량`으로 하며, 상대 앱이나 시스템의 미디어 음량을 바꾸지 않는다. |
| R-05 | 광고 수익 | 무료 이용과 광고 수익을 기본 모델로 한다. 광고의 표시·갱신 때문에 VEIL이나 상대 앱의 오디오가 중단되거나 작아지지 않아야 한다. |
| R-06 | Android와 iOS | 두 플랫폼 모두에서 핵심 기능을 제공하고, 동시 재생 지원 범위를 플랫폼별 실기기 결과로 확인한다. |

대표 흐름은 **VEIL에서 믹스 재생 → 유튜브로 이동 → 영상 소리와 VEIL 소리를 함께 듣기**다. 다른 앱으로 이동한 뒤에도 VEIL 재생을 유지할 수 있어야 한다. 상대 앱 자체의 백그라운드 재생 제한까지 VEIL이 해제할 수 있다는 의미는 아니다. 상세 조건은 [다른 앱과의 동시 재생 설계](audio-coexistence.md)를 따른다.

아래 항목은 논의 과정의 제안이며, 사용자가 확정한 음원 수나 완성된 구현으로 취급하지 않는다.

| 항목 | 현재 검토안 |
| --- | --- |
| 환경음·노이즈 라이브러리 | 흐르는 물, 시냇물, 비, 파도, 새소리, 바람, 환풍기, 화이트 노이즈, 핑크 노이즈, 브라운 노이즈의 10종 |
| 음악 라이브러리 | 잔잔한 피아노 3곡. 실제 음원과 이용 권한은 미확보 |
| 동시 음악 수 | 여러 환경음에 음악 1곡을 혼합 |
| 첫 화면 | 마지막 믹스와 음량을 기억한 정지 상태에서 열고, 한 번의 재생 조작으로 시작 |
| 재생 품질 | 부드러운 시작·종료·음원 전환, 반복 경계에서 끊김 최소화 |
| 음원 제공 | 기본 음원을 기기에 저장하여 오프라인 사용 지원 |
| 재생 상태 | 백그라운드·잠금 화면 재생과 현재 출력 장치 표시 검토 |
| 광고 배치 | 조작부와 떨어진 배너 1개. 재생 전 강제 광고와 오디오가 있는 광고는 초기 설계에서 제외 |
| 기술 구성 | Flutter와 AdMob을 검토하되, 오디오 검증 후 라이브러리와 네이티브 연동 방식을 결정 |

## 디자인과 기능의 경계

- 주 화면에는 재생·정지, 선택한 소리, 개별 음량, `VEIL 음량`, 소리 추가, 음악 변경, 출력 장치 상태를 우선 배치한다.
- 광고와 재생·음량 조작부를 분리하고, 급하게 켜야 하는 사용 흐름을 방해하지 않는다.
- 마이크를 이용한 주변 소리 수집이나 녹음 기능은 두지 않는다. 소음 분석을 위한 녹음 권한도 기본 요구에 포함하지 않는다.
- 소리를 겹쳐 주변 소리가 덜 두드러지게 하는 마스킹 제품으로 설계한다. 실제 ANC, 소음 제거율, 완전한 차음 효과를 보장하는 표현은 사용하지 않는다.
- 광고 SDK의 데이터 처리·동의·스토어 고지 범위는 SDK 선정 후 확인한다. 녹음하지 않는다는 설계만으로 개인정보 처리가 전혀 없다고 표시하지 않는다.

## 다음 개발 순서

1. 두 플랫폼에서 오디오 프로토타입을 만들고, 다른 앱과의 동시 재생을 먼저 검증한다.
2. 검증 결과로 오디오 라이브러리, 백그라운드 재생 구조, 지원 조건을 결정한다.
3. 미선정 UI 시안의 방향을 정하고 믹서·음원 선택 화면을 구체화한다.
4. 실제 사용 가능한 음원을 확보하고 광고 SDK를 결합한 뒤 동시 재생을 다시 확인한다.

현재 수용 테스트 상태는 **전 항목 미실시**다. 출시 통과 조건과 기록 항목은 [오디오 검증 시나리오](audio-coexistence.md#출시-통과-검증-시나리오)에 정리한다.
