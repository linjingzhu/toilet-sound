# 다른 앱과의 동시 재생 설계

작성일: 2026-10-12 · 상태: 검증 전 설계 초안

## 최우선 동작 계약

**VEIL은 유튜브 등 다른 앱의 소리와 함께 재생되어야 하며, VEIL의 동작으로 상대 앱을 멈추거나 상대 앱의 음량을 낮추면 안 된다.** 음량을 자동으로 낮추는 동작을 이 문서에서는 덕킹이라고 한다.

이 계약은 재생 시작뿐 아니라 소리 추가·삭제, 피아노 변경, 앱 전환, 광고 SDK 초기화와 광고 갱신에도 적용한다. VEIL의 개별 음량과 `VEIL 음량`은 VEIL 내부 오디오에만 적용한다. 음악을 바꾸거나 끌 때 환경음은 계속 재생한다.

현재 앱과 오디오 프로토타입은 구현되지 않았다. 아래 설정은 검증 후보이며, 모든 기기와 외부 앱에서 동시 재생이 보장된다는 선언이 아니다.

## 플랫폼별 검증 후보

### iOS

- `AVAudioSession`의 재생용 카테고리 `.playback`과 `.mixWithOthers` 조합을 우선 검토한다. Apple은 `mixWithOthers`를 다른 앱의 오디오와 혼합하는 옵션으로 제공한다. [Apple: mixWithOthers](https://developer.apple.com/documentation/avfaudio/avaudiosession/categoryoptions-swift.struct/mixwithothers)
- 다른 앱의 음량을 낮추는 `.duckOthers`는 사용하지 않는 방향으로 설계한다. 말소리 재생을 중단시킬 수 있는 `.interruptSpokenAudioAndMixWithOthers`도 사용하지 않는다. [Apple: duckOthers](https://developer.apple.com/documentation/avfaudio/avaudiosession/categoryoptions-swift.struct/duckothers), [Apple: interruptSpokenAudioAndMixWithOthers](https://developer.apple.com/documentation/avfaudio/avaudiosession/categoryoptions-swift.struct/interruptspokenaudioandmixwithothers)
- 앱 전환·잠금 화면에서 재생을 유지하는 구성, 시스템 중단 처리, 출력 장치 변경은 별도 확인한다. 믹싱 옵션 하나만으로 모든 백그라운드 동작이 완성되는 것은 아니다.
- Flutter 플러그인과 광고 SDK가 세션 카테고리·옵션을 다시 설정하는지 확인한다. 음원 변경이나 광고 초기화 뒤에도 의도한 설정과 동시 재생 동작을 유지해야 한다.

### Android

Android는 여러 앱의 오디오를 혼합할 수 있지만, 공식 문서는 오디오 포커스를 요청하고 포커스 변화에 대응하는 일반적인 재생 방식을 안내한다. 포커스 요청은 조건에 따라 다른 앱의 페이드아웃·정지·덕킹을 유발할 수 있다. [Android: Manage audio focus](https://developer.android.com/media/optimize/audio-focus)

- VEIL이 상대 앱의 포커스를 빼앗지 않도록 **오디오 포커스를 요청하지 않는 재생 구조**를 검증 후보에 포함한다. 이는 Android가 모든 상황의 동시 재생을 보장하는 공식 API라는 뜻이 아니다. 플랫폼 지침, 지원 OS, 실제 기기 동작을 평가한 뒤 채택 여부를 정한다.
- `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK`은 다른 앱의 음량을 줄일 수 있으므로 이 요구사항의 해법으로 취급하지 않는다.
- 오디오 플러그인이 자동으로 포커스를 요청하는지, 트랙 생성·음악 변경·광고 SDK 초기화가 별도의 요청을 일으키는지 확인한다.
- 백그라운드 재생에 필요한 서비스·알림·권한 구성과 시스템 중단 처리를 함께 검토한다. 단순히 포커스 요청을 생략하는 것으로 통화나 시스템 중단을 무시하지 않는다.

### 공통

한 환경음이나 음악의 변경 때문에 믹서 전체를 종료·재생성하지 않는 구조를 검토한다. 음원 재생 계층과 광고 계층에서 발생하는 오디오 설정 변경을 함께 추적한다. `VEIL 음량`은 내부 게인으로 처리하며, 시스템 전체 미디어 음량을 프로그램으로 조절하는 기능으로 구현하지 않는다.

## 유튜브 사용 조건을 구분한다

**유튜브를 화면에 띄우고 VEIL을 백그라운드로 재생하는 경우**를 가장 먼저 확인한다. 반대로 유튜브를 백그라운드에 두는 경우는 유튜브 자체의 이용 조건과 설정을 따로 기록한다.

YouTube 도움말은 백그라운드 재생의 이용 조건을 안내하며, 다른 앱이 오디오를 재생하는 동안 백그라운드 재생이 동작하지 않을 수 있는 제약을 명시한다. 따라서 유튜브의 화면 전환 자체에 따른 정지와 VEIL이 유발한 중단을 구분해야 한다. [YouTube: Background play isn't working](https://support.google.com/youtube/answer/7437614)

VEIL을 끈 대조 조건으로 같은 실행 순서를 먼저 확인한다. 외부 앱의 제한이 발견되면 재현 조건과 지원 범위를 기록하고, 그 제한을 우회하거나 모든 앱에서 동작한다고 표시하지 않는다.

## 출시 통과 검증 시나리오

모든 시나리오는 **Android와 iPhone 실기기에서 미실시** 상태다. 에뮬레이터나 문서 검토만으로 통과 처리하지 않는다.

| ID | 시나리오 | 통과 기준 | 현재 상태 |
| --- | --- | --- | --- |
| A-01 | VEIL 환경음을 재생한 뒤 유튜브로 이동하여 영상 재생 | 영상과 환경음이 동시에 들리며 VEIL이 유튜브를 정지·덕킹하지 않음 | 미실시 |
| A-02 | 상대 앱의 백그라운드 재생이 가능한 조건에서 상대 앱을 먼저 재생하고 VEIL 시작 | VEIL 시작으로 상대 앱이 정지하거나 작아지지 않음 | 미실시 |
| A-03 | 동시 재생 중 환경음 추가·삭제, 피아노 추가·변경·정지 | 상대 앱에 중단·덕킹이 없고 음악 변경 중 기존 환경음도 유지됨 | 미실시 |
| A-04 | 개별 음량과 `VEIL 음량` 변경, VEIL 일시정지·재개 | VEIL의 소리만 바뀌고 상대 앱과 시스템 음량은 유지됨 | 미실시 |
| A-05 | 동시 재생 상태에서 광고 SDK 초기화와 배너 로드·갱신 | 광고 오디오가 나오지 않으며 두 앱의 소리에 중단·덕킹이 없음 | 미실시 |
| A-06 | 다른 앱 전환과 화면 잠금·해제 | 각 조건의 지원 범위 안에서 VEIL 재생이 유지되고 상태 표시가 실제 재생과 일치함 | 미실시 |
| A-07 | 휴대폰 스피커·유선 이어폰·Bluetooth 전환과 연결 해제 | 출력 장치 상태가 실제 경로와 일치하고 갑작스러운 재생·음량 변화의 원인과 처리 방식이 확인됨 | 미실시 |
| A-08 | 통화와 시스템 오디오 중단 발생·종료 | 시스템 중단을 적절히 처리하고, 사용자 정지를 무시한 자동 재생이나 포커스 반복 요청이 없음 | 미실시 |
| A-09 | 유튜브 전경·백그라운드·잠금 화면을 VEIL 없이/함께 비교 | 유튜브 자체 제약과 VEIL이 유발한 중단이 구분되며 지원 조건이 문서화됨 | 미실시 |

각 실행에는 기기명, OS 버전, VEIL 빌드, 오디오 플러그인·광고 SDK 버전, 상대 앱 버전, 실행 순서, 출력 장치, 백그라운드 이용 조건, 예상·실제 결과를 기록한다. 테스트 기록에 주변 대화나 화장실 소리를 수집할 필요는 없다.

출시 전에는 A-01부터 A-05까지 두 플랫폼에서 통과해야 한다. 나머지 항목도 실제 지원 조건과 중단 처리 동작을 확정해야 한다. 핵심 조건이 실패하면 오디오 구조를 수정하고 다시 검증하며, 동시 재생을 지원한다고 선행 표시하지 않는다.

## 미결정 항목

- 오디오 라이브러리, 네이티브 연동 범위, Android 포커스 처리 방식
- 최소 지원 OS와 실기기 검증 대상
- 잠금 화면·출력 장치 변경·중단 후 재개 정책
- 광고 SDK 적용 후의 지원 범위와 회귀 검증 결과

Flutter와 AdMob은 현재 검토 방향이며, 이 문서에는 확정된 패키지 버전이나 구현 완료 상태가 없다.
